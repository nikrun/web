# Packages

Nikrun uses a decentralized, source-first package model that requires no central package registry. Dependencies are declared directly in `nik.yaml` and can reference local directories, Git repositories, or static archive URLs. Resolved versions and SHA-256 checksums are pinned in `nik.lock` for reproducible builds across machines and CI.

## Declaration

Add packages under `dependencies:` (or platform/profile-specific `dependencies:` sections) in `nik.yaml`:

```yaml
dependencies:
  # 1. Local directory (unpublished library or workspace sibling)
  my-utils: ../my-utils

  # 2. Git repository URL + '@<semver>' or '@<commit>'
  lsp-protocol: https://github.com/nikrun/lsp-protocol@^0.2.0
  pinned-lib: https://codeberg.org/example/fpc-lib@4f025e77

  # 3. Direct archive (.zip / .tar.gz / .tgz) — remote URL or local file
  vendor-sdk: https://packages.example.com/pascal/vendor-sdk-2.1.0.zip
  local-bundle: ./vendor/bundle-1.0.0.zip

  # 4. Expanded mapping (monorepo subpath, legacy repo without nik.yaml, or local override)
  legacy-lib:
    url: https://github.com/example/legacy-pascal
    version: ~1.4.0
    unitPaths: [Source, Source/Common]

  monorepo-pkg:
    url: https://github.com/nikrun/cli
    version: ^0.1.0
    subpath: lsp-protocol

  dev-override:
    url: https://github.com/nikrun/lsp-protocol
    path: ../lsp-protocol
```

### Source Kinds

`nik` determines the dependency kind strictly from the prefix and suffix:

| Kind | Prefix | Suffix | Notes |
| :--- | :--- | :--- | :--- |
| Local path | `./`<br>`../`<br>`/`<br>`\`<br>`<Drive>:` | *(directory)* | Compiled directly from disk; not written to `nik.lock`. |
| Local archive | `./`<br>`../`<br>`/`<br>`\`<br>`<Drive>:` | `.zip`<br>`.tar.gz`<br>`.tgz` | Extracted to the package cache and SHA-256 recorded in `nik.lock`. |
| Git repository | `https://`<br>`http://`<br>`ssh://`<br>`file:///` | `@<semver>`<br>`@<commit>` | Moving branch names (e.g. `@main`) are rejected for reproducibility. |
| Remote archive | `https://`<br>`http://`<br>`ssh://`<br>`file:///` | `.zip`<br>`.tar.gz`<br>`.tgz` | Downloaded to the package cache and SHA-256 recorded in `nik.lock`. |

> [!TIP]
> To inspect a Git repository's available SemVer tags, current `HEAD` commit hash, and ready-to-paste `nik.yaml` snippet, run:
> ```bash
> nik pkg info https://github.com/nikrun/cli
> ```

## Version Constraints & Minimal Version Selection (MVS)

Supported SemVer 2.0 constraints for Git tags (`v1.2.3` or `1.2.3`):

- **Caret (`^1.2.0`):** Compatible updates (`>=1.2.0 <2.0.0`; for `^0.2.1`, `>=0.2.1 <0.3.0`).
- **Tilde (`~1.2.0`):** Patch-level updates (`>=1.2.0 <1.3.0`).
- **Exact (`1.2.3` or `=1.2.3`):** Exact version match.
- **Comparators (`>=1.0.0`, `<2.0.0`):** Explicit version bounds.

Because Free Pascal shares a flat global unit namespace per compilation, `nik` resolves transitive dependencies via **Minimal Version Selection (MVS)**:

1. **Locked reuse:** If `nik.lock` already contains a version satisfying all constraints in the graph, `nik` reuses it without querying remote servers.
2. **Fresh resolution:** For unlocked dependencies, `nik` picks the **lowest SemVer tag** that satisfies every constraint across the dependency graph.
3. **Explicit upgrade:** Running `nik pkg update` queries remote tags and upgrades `nik.lock` to the **newest compatible SemVer tag** within `nik.yaml` bounds.

## Commands

`nik build` fetches missing packages automatically, so you rarely need to run package commands manually except to pre-warm caches, inspect dependencies, or upgrade `nik.lock`:

```bash
nik pkg fetch                    # Download & verify all dependencies and sync nik.lock
nik pkg fetch --locked           # CI check: verify nik.lock and populate cache without changes
nik pkg update                   # Upgrade all SemVer packages in nik.lock to newest compatible tags
nik pkg update lsp-protocol      # Upgrade a single package in nik.lock
nik pkg list                     # List resolved direct & transitive dependencies
nik pkg info <git-url>           # Show remote SemVer tags and HEAD commit
```

## Cache & `nik.lock`

Downloaded packages are extracted once into the immutable user-scope **Package Cache** (`~/.nikrun/cache/pkg/`). `nik` fetches Git tags via Git Smart HTTP and downloads release archives over HTTPS directly on GitHub, GitLab, and Codeberg/Gitea—falling back to the `git` CLI only for SSH or custom Git servers.

Commit `nik.lock` to version control alongside `nik.yaml`:

```yaml
# Auto-generated by nik. Commit this file to version control.
lockVersion: 1

packages:
  - id: https://github.com/nikrun/lsp-protocol
    kind: git
    url: https://github.com/nikrun/lsp-protocol
    version: 0.2.0
    rev: 8f3a19c4d2e0b71a9c54f8e1203948576abcdef0
    integrity: sha256-9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08
```

For `kind: git`, `integrity` hashes the sorted relative file paths and contents (`sha256-<hex>`), ensuring identical cryptographic verification across Windows, Linux, and macOS regardless of whether the package was fetched as an HTTP `.zip` archive or via `git` CLI.
